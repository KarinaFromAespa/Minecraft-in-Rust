# Minecraft in Rust

Every major Minecraft Java Edition release — **1.0 → 26.3, 103 releases** — rewritten
in Rust for desktop. **Eleven releases** — the era templates — are held to full
one-to-one behavioural parity with their own jar; the other **ninety-two** are
delta-verified: correct on everything that release changed, correct on data, and
honest about the rest in a signed ledger. Both are reference reimplementations
from decompiled jars, verified against the running jar with parity harnesses,
the same method that produced the 26.3 rewrite.

## Try it

The 1.21.7 port is in open playtest. The latest test build is on the
**[releases page](https://github.com/KarinaFromAespa/Minecraft-in-Rust/releases)**
(currently [1.21.7 test build #10](https://github.com/KarinaFromAespa/Minecraft-in-Rust/releases/tag/1.21.7-build-10)):
the launcher for Windows and Linux, plus the 1.21.7 game build for
Windows. No Microsoft account is needed.

1. Download `horizon-launcher-1.21.7-windows.zip` and
   `horizon-client-1.21.7-windows.zip` from the release, and unzip both.
2. Run `horizon-launcher.exe`.
3. Press Prepare. The launcher downloads the 1.21.7 game files from
   Mojang and prepares them — a few minutes the first time.
4. Import a game build: pick `horizon-client.exe` from the unzipped
   game build.
5. Press Play, then create or open a world.

Build #8 fixes the first world load sticking on "Loading terrain…"
and the blank menu icons. If you already prepared with an earlier
build, press Prepare once more to pick the icons up.

Requirements: Windows 10/11 x64 (or Linux x64 for the launcher; the
game build is Windows-only for now), a few GB free, a GPU with Vulkan
or DirectX 12. Keep render distance at 12 — the slider allows 128 and
that can crash smaller GPUs. Report problems as
[issues](https://github.com/KarinaFromAespa/Minecraft-in-Rust/issues), with
what you did, a screenshot or clip, the world seed, and the game log
(in the launcher: Console, then Share log).

## Base

The foundation is the upstream desktop **horizon-rust** project, whose version-port
pipeline (`tools/version_port.py`, design in its `docs/version-ports.md`) was built to
turn each new Minecraft release into Rust. This programme runs that pipeline
*backward* through history and keeps every version as a finished line.

The full plan — era decomposition, the per-version pipeline, the hard problems and
their workarounds, sequencing and gates — is in **[docs/ROADMAP.md](docs/ROADMAP.md)**.

## Organization

- **`main` is the only branch.** It holds the plan, the version index, the shared
  pipeline tooling, and every version's rewritten code.
- **Each version lives in its own directory: `versions/<id>/`**
  (e.g. `versions/1.21.11`, `versions/1.8.9`), with its port notes and parity
  status documented alongside the code.
- **[VERSIONS.md](VERSIONS.md)** is the index: all 103 releases grouped by
  architecture era, each with its location and status.
- Era lines are the maintained units; a finished era eventually **freezes** —
  a parity-verified old release stays correct forever.

## Rules

- **Nothing Mojang-derived is ever committed.** Jars, mappings and decompiled
  sources are development-time reference only; they live in `.local/`, which is
  git-ignored. The product is only the reimplemented Rust code.
- Players prepare each version's data from **their own** Minecraft copy
  (`horizon-prepare`), exactly as the 26.3 rewrite works today.
- Every version directory pins itself with a `research-lock.json` (version, jar
  hashes, Java major) — the version a build targets is never a guess.

is dropped. Porting has resumed down the 26.x

`VERSIONS.md` come from it today and migrate to generated

published trees are dispatched to GitHub Actions (`port-verify`
workflow). See `VERSIONS.md` for the per-version state, the roadmap §5
for sequencing and §6 for the remaining owner decisions.
